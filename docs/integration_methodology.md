# Dataset integration methodology and validation record

## Data identity

The group proposal cites [Kaggle Student dropout prediction dataset](https://www.kaggle.com/datasets/meharshanali/student-dropout-prediction-dataset) (10,000 records) and [UCI dataset 697](https://archive.ics.uci.edu/dataset/697/predict%2Bstudents%2Bdropout%2Band%2Bacademic%2Bsuccess) (4,424 instances, 36 features, no missing values on the repository page, three classes). The separate `download_datasets.py` script obtains both files and records local schema/quality reports. Record access date, downloaded version and checksums when collecting final reproducibility evidence. The Kaggle page schema must be confirmed from the downloaded CSV.

## Processing sequence

1. Upload each CSV under its declared source. Reject non-CSV files, files larger than 20 MiB, blank or duplicate headers, empty files, and unreadable CSV data.
2. Store a UUID filename and metadata record; report dimensions, dtypes, missing cells, missing percent, unique counts, and exact duplicate-row count. Duplicate records are flagged but are not silently deleted.
3. Preview the original uploaded columns and sample records. Retain source files unchanged.
4. Resolve mapping aliases case/punctuation-insensitively, but require a unique match. Apply only the allowlisted feature operations in `pipeline.py`.
5. Rank grades within each source independently, calculate the declared trends/proxies, preserve source provenance, and mark missing harmonised features. Keep source-specific target values.
6. Concatenate the two mapped tables row-wise. Student records are not linked across datasets and row order is not identity.
7. Default to original outcomes. Create binary dropout labels only in an explicit `binary_dropout` output using the configured label map. Keep the UCI Dropout/Enrolled/Graduate experiment separate.
8. Split before fitting imputers, encoders, scalers, feature selection or resampling. Use training-only fitting and apply the frozen transform to validation/test data. Keep the source indicator outside model inputs for the standard experiment and report metrics by source.

## Checks before reporting integrated results

- Verify mapping aliases and meanings against both data dictionaries and CSV headers.
- Confirm every mapped output column is generated from its declared source column(s).
- Confirm output rows equal the sum of source row counts and each row has exactly one source label.
- Check target value counts per source; confirm all binary labels map and originals remain available.
- Compare each source's row/column counts, missingness, duplicate counts, target distribution and numeric summaries with the integrated result.
- Verify no ID, final outcome, or post-outcome field is used as a predictor; source-only columns and indicators are reviewed.
- Run source-stratified splits, per-source metrics, and transfer tests in both directions. Use a pooled score only as one result.
- Apply SMOTE only within training folds. Pick risk cutoffs without using the held-out test set.

The runtime API supplies raw dataset validation and before/after row and target counts. Model comparison, subgroup evaluation, and transfer scores are experiment outputs to be generated by the ML team after real datasets and mappings have been confirmed.
